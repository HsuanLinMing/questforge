# 故事規範重寫需求摘要

這份文件用來說明「故事規範重寫」的方向，供後續新聊天室直接閱讀並接續工作。

## 目標

重寫目前的故事規範，讓故事生成方式從「硬規則驅動」改成「樣本風格驅動」。

新的規範應該主要根據 `samples/samples/` 裡整理出的喜歡故事樣本來生成，而不是被大量固定規則、禁止條款、教條式目標綁住。

## 核心原則

1. 只保留霏霏、樂樂的人格個性與角色核心。
2. 其他像是核心目標、價值宣言、硬性教條、過多的禁止條款，都可以大幅刪除或重寫。
3. 不希望規範再寫成大量「一定要 / 不可以 / 禁止 / 必須」的寫死方式。
4. 希望 AI 生成時優先參考故事樣本的共同風格，而不是機械地套模板。
5. 生成結果要更有彈性、更像範例故事的趣味和節奏。

## 必須保留的部分

1. 霏霏、樂樂的人設核心與互動化學反應。
2. 程式真正依賴的最小結構契約。
3. `STRUCTURE｜結構` 這一層骨架建議保留。
4. 任何會影響生成流程、節點命名、輸出格式、驗證流程的必要結構，都不能直接拿掉。

## 不希望保留的部分

1. 過度僵硬的世界觀限制。
2. 過多的硬規則與禁止條款。
3. 太像說教、價值宣導、教育口號的規範內容。
4. 容易把故事拉回固定模板的強制寫法。
5. 不是程式相容性必要的限制性規則。

## 想要的新規範形態

新的故事規範建議改成三層：

### 1. `CHARACTERS｜角色核心`

只保留霏霏、樂樂的人格個性、說話習慣、互動方式、角色分工、人設邊界。

### 2. `STRUCTURE｜結構`

只保留程式需要的最低限度骨架與必要節點格式，避免生成流程壞掉。

### 3. `STYLE DNA｜風格母型`

根據 `samples/samples/` 裡的樣本，反推故事真正的共同風格，包含：

- 敘事節奏
- 對話口氣
- 趣味感
- 情緒轉場
- 案件如何展開
- 案件如何收尾
- 人物互動手感
- 線索埋法與回收方式

## 明確方向

這次要的是：

「保留系統可用性，但把故事創作主導權交還給樣本風格。」

不是整份舊規範照搬，也不是完全不要任何結構，而是：

- 保留必要殼
- 重寫大部分內容
- 用樣本故事決定新規範的風格
